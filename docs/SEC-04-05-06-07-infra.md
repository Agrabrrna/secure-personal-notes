# SEC-04 s/d SEC-07 — Panduan Infra (Ubuntu/VM)

## SEC-04 HTTPS (Nginx + self-signed OpenSSL)
```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/spn.key -out /etc/ssl/certs/spn.crt
# Nginx: listen 443 ssl; ssl_certificate/cert_key; proxy_pass ke gunicorn/flask
# server :80 return 301 https://$host$request_uri;
sudo nginx -t && sudo systemctl reload nginx
```
Bukti: akses https (warning self-signed wajar), redirect HTTP→HTTPS, `curl -I http://...`.

## SEC-05 Linux Hardening
- Admin non-root (sudo), app jalan sebagai service account non-login.
- Permission ketat: `.env`/kunci `600` milik service, DB `600`, kode `750`.
- SSH: nonaktifkan root login/password auth (pakai key), ubah port opsional, `AllowUsers`.
- fail2ban jail `sshd` (dan opsional auth app) untuk batasi login gagal.
- `sudo apt update && sudo apt upgrade -y`; unattended-upgrades.
Bukti: `sshd_config`, status fail2ban, `ls -l` permission, user/service.

## SEC-06 Firewall (UFW) + Nmap
```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH   # atau port SSH
sudo ufw allow 80/tcp    # redirect saja
sudo ufw allow 443/tcp
sudo ufw enable && sudo ufw status verbose
```
Bukti: `nmap -sS -Pn <VM_IP>` **sebelum** (port lebih banyak/berbeda) dan **sesudah** (hanya yang diizinkan).

## SEC-07 Backup & Restore
- Backup otomatis terenkripsi via cron, permission ketat, retensi (lihat `scripts/backup.sh`).
- Restore: dekripsi + salin DB ke `instance/` saat service stop, verifikasi data utuh.
```bash
# contoh enkripsi backup: gpg --symmetric --cipher-algo AES256 -o backup.db.gpg app.db
# atau openssl enc -aes-256-cbc -pbkdf2 -salt -in app.db -out backup.db.enc
```
Bukti: log cron, file backup terenkripsi, uji restore dan buka data.
